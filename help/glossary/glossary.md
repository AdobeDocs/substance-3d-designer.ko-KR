# Designer에서 사용되는 용어 및 개념에 대해 알아봅니다.

## #&#x200B;

|  |  |
| --- | --- |
| <b><span id="three-d-scene" data-preserve-html="true"></span>3D 장면</b> | 3D 공간의 시각화를 표현하고 애니메이션을 적용하는 데 관련된 개체 및 데이터 컬렉션입니다.<ul data-preserve-html="true"> <li data-preserve-html="true">[망](#mesh)</li> <li data-preserve-html="true">[재질](#material)</li> <li data-preserve-html="true">카메라</li> <li data-preserve-html="true">조명</li> <li data-preserve-html="true">애니메이션</li> <li data-preserve-html="true">시뮬레이션</li> <li data-preserve-html="true">...</li> </ul>3D 장면을 저장하기 위해 [많이 사용되는 파일 형식](https://www.adobe.com/kr/products/substance3d/discover/3d-files-formats.html)으로는 Pixar의 [USD](#usd)과 Autodesk의 FBX가 있습니다. 모든 파일 형식은 이러한 구성 요소를 지원하지 않습니다 |

## A

|                                                                                        |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
|----------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="alpha" data-preserve-html="true"></span>Alpha 채널</b> | 불투명도를 설명하는 데 주로 사용되는 색상 이미지의 네 번째 채널입니다. |
| <b><span id="ambient-occlusion" data-preserve-html="true"></span>주변 오클루전</b> | 노출이 적기 때문에 도달하기 어려운 표면에서의 주변 광의 감쇠입니다. |
| <b><span id="anisotropy" data-preserve-html="true"></span>비등방성</b> | 방향에 종속되는 속성입니다. 다른 말로, 다른 축에서 측정되거나 관찰될 때 다른 결과를 제공하는 것이다.<br><br>비등방성 물질은 어디에서나 볼 수 있는 것처럼 보이며 비등방성 필터가 모든 방향으로 균일하게 적용되지 않습니다. |
| <b><span id="aov" data-preserve-html="true"></span>AOV</b> | AOV(임의 출력 변수)는 [렌더링](#rendering)에서 깊이, 표준 또는 사용자 지정 데이터와 같이 렌더링에서 출력할 수 있는 추가 데이터 채널을 설명하는 데 사용되는 용어입니다. |
| <b><span id="api" data-preserve-html="true"></span>API</b> | API(응용 프로그래밍 인터페이스)는 사용자가 다른 프로그램 응용 프로그램의 함수 및 절차에 액세스할 수 있도록 하는 함수 및 절차의 모음입니다.<br><br>API는 사용자와 프로그램 간에 제어되고 안전한 계층을 제공합니다. 그것은 또한 그 프로그램을 더 쉽게 상호 작용하고 더 널리 접근할 수 있게 하기 위해 다른 프로그래밍 언어를 사용할 수 있다.<br><br>Designer은 데이터를 조작하고 사용자 지정 도구를 빌드하고 작업 과정을 가속화하기 위한 다양한 기능에 쉽게 액세스할 수 있는 [Python API](../scripting/scripting.md)를 제공합니다. |
| <b><span id="atomic-node" data-preserve-html="true"></span>Atomic node</b> | 그래프의 기본 구성 요소입니다. 모든 [인스턴스 노드](#instance-node)를 원자 노드의 그래프로 나눌 수 있습니다.<br>각 그래프 유형에는 고유한 원자 노드 집합이 있습니다. |

## B

|                                                                                          |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
|------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="baking" data-preserve-html="true"></span>굽기</b> | 3D 모델에서 정보를 계산하고 결과를 [텍스처](#texture)에 저장하는 프로세스입니다. 데이터는 모델의 [UV](#uv)에 따라 텍스처에 배치됩니다. |
| <b><span id="base-color" data-preserve-html="true"></span>기본 색상</b>(알베도) | PBR 금속 거칠기 [음영](#shader) 모델을 사용하여 정의된 [재질](#material)의 채널입니다.<br>기본 색상은 조명 정보가 없는 표면의 색상을 지정합니다.<br><br>확산[&#128279;](#diffuse)과 혼동해서는 안 됩니다. |
| <b><span id="base-parameter" data-preserve-html="true"></span>기본 매개 변수</b> | [비트맵](#bitmap)을 계산하는 Substance 그래프의 모든 노드에 공통적인 매개 변수입니다.<br><br>여기에는 해상도([출력 크기](#output-size)) 및 [비트 심도](#bit-depth)([출력 형식](#output-format)) 또는 [타일링](#tiling) 모드와 같은 비트맵 계산 방법과 같은 비트맵의 핵심 측면이 포함됩니다.<br><br>기본 매개 변수는 노드를 호스팅하는 그래프 또는 업스트림에서 다른 노드에서 [상속](#inheritance)되는 경우가 많습니다. |
| <b><span id="bilinear-filtering" data-preserve-html="true"></span>쌍선형 필터링</b> | [텍스처 샘플](#texture-sampling)이(가) 픽셀의 중심에서 정확하게 수행되지 않은 경우 컴퓨터 이미징에 사용되는 보간 프로세스입니다.<br><br>예를 들어, 이 문제는 이미지를 확대할 때 발생할 수 있습니다. |
| <b><span id="bit-depth" data-preserve-html="true"></span>비트 심도</b> | 텍스처에 픽셀 값을 저장하는 데 사용되는 비트 수입니다. 비트 심도가 높을수록 더 많은 값을 인코딩할 수 있으므로 그라디언트가 더 부드러워집니다.<br><br>값의 유형에 따라 다른 비트 심도를 사용할 수 있습니다. - 8비트(0 - 255) 또는 16비트(0 - 65,535)를 사용하여 정수 값을 인코딩할 수 있습니다. - 부동 소수점 값은 16비트(+32767.9999 ~ -32768.0 ) 또는 32비트(-3.4E+38 ~ +3.4E+38)로 인코딩할 수 있습니다.<br><br>낮은 동적 범위 이미지는 정수 값을 사용하여 0에서 1까지의 단계를 인코딩합니다. High Dynamic Range 이미지는 부동 소수점 값을 사용하여 원시 숫자 값을 인코딩합니다.<br><br>Substance 그래프에서 비트 심도는 [출력 형식](#output-format) 매개 변수로 제어됩니다. |
| <b><span id="bitmap" data-preserve-html="true"></span>비트맵</b> | 디지털 이미지입니다. 두 가지 유형의 이미지가 가장 일반적입니다.<ul data-preserve-html="true"> <li data-preserve-html="true">회색 음영 이미지에는 광도(L),</li> <li data-preserve-html="true">색상 이미지에는 빨강, 녹색 및 파랑(RGB)의 세 가지 채널이 있습니다. 네 번째 것은 불투명도에 자주 사용되는 [알파](#alpha)(A)입니다. Designer의 색상 이미지는 항상 RGBA입니다.</li> </ul>  비트맵은 값의 그리드(grid)로 간주될 수 있습니다. 그리드의 각 셀은 픽셀이며, 이것은 &#39;그림 요소&#39;의 약어입니다. 픽셀은 채널당 하나의 값을 저장합니다. 해당 값의 유형은 비트맵의 [비트 심도](#bit-depth)에 따라 달라집니다. |

## C

|                                                                                                                                          |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
|------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="cache" data-preserve-html="true"></span>캐시</b>(메모리) | 데이터 모음 - 예: 노드의 [기본 매개 변수](#base-parameter) 및 출력 이미지 - 재사용할 메모리에 저장됩니다.<br><br>캐시는 [Substance 엔진](#substance-engine)에서 변경된 그래프의 부분만 다시 계산하도록 하여 그래프 계산 속도를 크게 높입니다. 노드 연결 및 매개 변수를 변경할 때 앞에 있는 모든 노드는 이러한 변경 내용의 영향을 받지 않으므로 그래프를 업데이트하기 위해 [평가](#evaluation)를 다시 수행할 필요가 없습니다. 대신 캐시가 사용됩니다.<br><br>큰 그래프에서 고해상도 및 비트 심도를 사용하여 작업할 때 캐시의 메모리 점유율이 상당할 수 있습니다. |
| <b><span id="channel-packing" data-preserve-html="true"></span>채널 패킹</b> | 개별 이미지가 단일 색상 이미지의 RGB(A) 채널에 팩킹되는 최적화 기술입니다.<br><br>예를 들어, RMA 텍스처는 [거칠기](#roughness) 맵(R), 금속도 맵(M) 및 [주변 오클루전](#ambient-occlusion) 맵(A)이며 모두 단일 색상 텍스처로 압축되어 있습니다.<br><br>또 다른 일반적인 기법은 회색 음영 텍스처를 [표준 맵](#normal-map)의 파란색 채널에 패킹을 설정하는 것입니다. 이는 표준 벡터의 &#39;위&#39; 구성 요소인 파란색 채널이 런타임에 다시 계산될 수 있기 때문입니다.<br><br>RGBA 병합[&#128279;](../compositing-graphs/nodes-reference-for-com/node-library/filters/channels/rgba-merge/rgba-merge.md) 노드는 이 기술을 구현하는 데 유용합니다. |
| <b><span id="color-space" data-preserve-html="true"></span>색상 공간</b> | 색상 범위의 표시 방법에 대한 정의입니다.<br>특정 색상을 디지털 방식으로 인코딩 및 디코딩하려면 사용된 숫자를 이해하기 위해 이러한 정의가 필요합니다.<br><br>이미지 파일에는 지정된 색상 공간을 사용하여 색상 값이 저장되므로 이러한 색상이 해당 색상 공간을 지원하는 디스플레이에서 충실하게 재현될 수 있습니다. 디스플레이는 주어진 컬러 공간을 완전히 또는 부분적으로 지원할 수 있게 하는 특정 컬러 재생 능력들을 갖는다.<br><br>원시 데이터 - 예: [표준 맵](#normal-map) - 이러한 색상은 시각화되지 않으며 해당 데이터에 변환을 적용해서는 안 되기 때문에 항상 선형 색상 공간에서 인코딩 및 디코딩됩니다.<br><br>sRGB는 광범위하게 지원되는 색상 공간입니다. 그 밖에 인기 있는 색상 공간으로는 Adobe RGB, Rec. 2100 및 ProPhoto RGB. |
| <b><span id="cooking" data-preserve-html="true"></span>요리</b>(<span id="compilation" data-preserve-html="true"></span>컴파일) | 데이터를 다른 언어로 번역하여 신속하고 효율적으로 실행할 수 있는 과정이다.<br>Substance 그래프의 결과를 계산하려면 먼저 그래프를 컴파일해야 합니다. 컴파일이 그래프 [평가](#evaluation) 프로세스의 일부입니다.<br><br>이 컴파일은 병합된 그래프에서 수행됩니다. 즉, 모든 [인스턴스 노드](#instance-node)가 소스 그래프로 &#39;대체&#39;되어 하나의 더 큰 그래프가 남고 해당 그래프가 컴파일된 것입니다.<br><br>컴파일된 그래프는 편집할 수 없습니다. [정적](#static-parameter) 매개 변수가 잠기고 숨겨진 상태에서 [동적](#dynamic-parameter)인 경우 노출된 매개 변수는 계속 사용할 수 있습니다. |
| <b><span id="culling"></span>컬링</b> | [렌더링](#rendering) [3D 장면](#three-d-scene)에 대한 최적화 기법으로, 표시되지 않을 때 렌더링 계산에서 형상을 제거합니다.<br><br>여기에는 카메라의 절두체(*절두체 컬링*) 외부의 개체 또는 다각형이 포함될 수 있으며, 카메라에서 반대 방향으로 향하거나(*백페이스 컬링*) 다른 불투명 개체에 의해 완전히 숨겨집니다(*오클루전 컬링*). |

## D

|                                                                                        |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
|----------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="dependency" data-preserve-html="true"></span>종속성</b> | 파일 A가 없을 때 파일 B가 의도한 대로 작동하지 않는 방식으로 다른 파일 B에서 사용하는 파일 A입니다.<br><br>패키지[&#128279;](#package)의 종속성은 그 안의 그래프, 이미지 파일, 글꼴 등을 참조하기 때문에 다른 패키지가 될 수 있습니다.<br><br>패키지는 종속성에 대한 경로를 저장하고, 해당 경로에서 종속성을 찾을 수 없는 경우 경고가 발생합니다. 종속성 누락으로 인해 그래프에서 [고스트 인스턴스 노드](#ghost-instance-node)가 발생할 수도 있습니다. |
| <b><span id="diffuse" data-preserve-html="true"></span>확산</b> | PBR Specular 광택 [음영](#shader) 모델을 사용하여 정의된 [재질](#material)의 채널입니다. 확산 은 켜져 있을 때 표면의 색상을 지정합니다.<br><br>기본 색상(알베도) [&#128279;](#base-color)과 혼동해서는 안 됩니다. |
| <b><span id="directx" data-preserve-html="true"></span>DirectX</b> | 멀티미디어 컨텐츠를 처리하기 위한 API 컬렉션입니다. 3D API Direct3D는 비디오 게임 개발 및 기타 3D 산업에서 널리 사용됩니다.<br><br>Direct3D는 텍스처의 원점(즉, (0, 0) 좌표)을 *왼쪽 위*(Y 아래)에 둔 반면 [OpenGL](#opengl) API는 이를 *왼쪽 아래*(Y 위)에 둡니다.<br><br>이것은 DirectX [표준 맵](#normal-map)에 OpenGL과 비교하여 *반전된 녹색 채널*&#x200B;이 있음을 의미합니다. 실제로, 초록색 채널은 법선벡터의 Y좌표를 호스팅한다. |
| <b><span id="displacement" data-preserve-html="true"></span>변위</b> | 3D 모델의 [정점](#vertex)을(를) [표준](#normal)을 따라 이동하는 프로세스입니다.<br><br>변위는 [테셀레이션](#tessellation) 및 [표준 맵](#normal-map)과 함께 사용되어 표면에 세밀한 디테일을 모델링하는 경우가 많습니다. |
| <b><span id="dynamic-parameter" data-preserve-html="true"></span>동적 매개 변수</b> | 값이 변경될 수 있는 매개 변수입니다. 즉, 값이 상수가 아닌 매개 변수는 모두 동적입니다.<br><br><br>여기에는 노출된 매개 변수, 노출된 매개 변수의 영향을 받는 모든 매개 변수 및 [텍스처의 샘플링](#texture-sampling)의 영향을 받는 모든 매개 변수 값이 포함됩니다.<br><br>반대로 [정적 매개 변수](#static-parameter)에서는 그래프를 [SBSAR 파일](#sbsar-file)로 컴파일한 후 동적 매개 변수 값을 즉시 조정할 수 있습니다. |

## E

| <b><span id="polycount" data-preserve-html="true"></span>Polycount</b> | 3D [메시](#mesh)의 다각형의 양입니다. 실제로 polycount는 &#39;polygon count&#39;에 비해 작습니다.<br><br>더 많은 다각형은 더 미세한 세부 사항을 모델링할 수 있습니다. 폴리카운트가 낮은 메시를 &#39;낮은 폴리&#39;라고 하며, 폴리카운트가 높은 메시를 &#39;높은 폴리&#39;라고 합니다. |
| <b><span id="primary-input" data-preserve-html="true"></span>기본 입력</b> | 해당 노드가 [기본 매개 변수](#base-parameter) 값을 상속하는 [인스턴스 노드](#instance-node)의 입력 커넥터입니다.<br><br>기본 입력은 해당 커넥터에 작은 점으로 표시되고 &#39;(기본) 접미사는 레이블에 표시됩니다.<br><br>둘 이상의 입력이 있는 노드를 사용할 때는 해당 입력 중 어느 것이 기본 입력이고 그래프 전체에서 [상속](#inheritance)에 미치는 영향에 대해 유의하는 것이 *적극*&#x200B;입니다. |
| <b><span id="procedural" data-preserve-html="true"></span>절차</b> | 수동으로 만드는 것이 아니라 컴퓨터 알고리즘을 따라 만들 데이터 또는 아티팩트의 특성입니다.<br><br>Designer은 알고리즘이 노드 그래프로 디자인된 절차 작업 과정을 사용합니다.<br> <br><br>절차 워크플로를 사용하면 알고리즘과 해당 매개 변수를 수정하여 변경 및 조정을 빠르게 생성할 수 있으므로 반복이 더 빨라집니다.<br><br>알고리즘으로 결과가 완전히 생성되면 그 결과는 구어적으로 &#39;100% 절차&#39;라고 합니다. 절차 생성은 때때로 &#39;proc-gen&#39;으로 단축됩니다.<br><br>Designer 노드 라이브러리의 대부분의 생성기는 결과를 생성하기 위해 입력 이미지가 필요하지 않다는 점에서 100% 절차입니다. |
| <b><span id="publishing" data-preserve-html="true"></span>게시(SBSAR)</b> | Designer에서 게시란 [패키지](#package)를 SBSAR 보관 파일로 내보내는 것을 말하며, 여기에는 [컴파일된](#compilation) 버전의 그래프, 해당 리소스([비트맵](#bitmap), 글꼴 등), 해당 사전 설정과 [메타데이터](#metadata)가 포함됩니다.<br><br>생성된 [SBSAR 파일](#sbsar-file)은 [Substance 3D 플러그인](https://substance3d.adobe.com/plugins/)을 통해 다른 Substance 3D 응용 프로그램이나 서드파티 응용 프로그램에서 배포되고 사용될 수 있습니다. |

| <b><span id="udim" data-preserve-html="true"></span>UDIM</b>(UV 타일) | [UV](#uv) 공간을 고유한 숫자 식별자를 사용하여 타일로 분할하는 표준으로, 각 타일에 서로 다른 [텍스처](#texture)를 할당할 수 있습니다.<br><br>UDIM 워크플로우는 VFX 파이프라인에서 흔히 사용됩니다. 이 파이프라인에서는 충실도가 높은 에셋에 너무 많은 세부 사항이 필요하기 때문에 고해상도 텍스처가 여러 개 필요합니다. 이 경우 에셋의 [UV](#uv)이(가) 여러 UDIM(또는 UV 타일)에 걸쳐 정렬됩니다.<br><br>Designer은 UDIM 작업 과정을 지원하며 UDIM마다 다른 Substance 그래프를 할당할 수 있습니다. |
| <b><span id="usd" data-preserve-html="true"></span>USD</b>(또는 OpenUSD) | [Universal Scene Description](https://openusd.org/release/index.html)&#x200B;(USD)는 Pixar에 의해 빌드된 3D 장면 설명 형식으로, 응용 프로그램과 플랫폼 간의 상호 운용성과 데이터 교환을 위해 빌드되었습니다.<br><br>USD 파일에는 장면에 사용된 데이터의 정의와 해당 장면의 구성이 포함됩니다. 모델, 재료, 카메라, 애니메이션, 시뮬레이션 등 모든 작업이 포함됩니다.<br><br>USD 파일에는 응용 프로그램이 해당 데이터를 올바르게 읽고 사용할 수 있는 USD 플러그인에 액세스할 수 있는 경우 모든 유형의 데이터가 포함될 수 있습니다.<br><br>Adobe은 형식 개발 및 표준화에 적극적으로 기여하는 3D 업계 전문가의 컨소시엄인 [OpenUSD를 위한 Alliance](https://blog.adobe.com/en/publish/2023/08/01/powering-3d-interoperability-continued-collaboration-through-openusd)에 참여하고 있습니다. |
| <b><span id="uv" data-preserve-html="true"></span>UV</b> | UV는 2D 공간에서 3D 모델을 나타냅니다. 2D 공간에서 2D 이미지를 3D 공간의 모델 표면에 매핑하는 데 사용됩니다.<br><br>UV를 만드는 과정은 종종 솔기를 펼쳐 납작하게 만드는 것으로 설명됩니다. |
